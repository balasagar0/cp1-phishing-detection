## 1. The system in one paragraph

Three trained detectors score single messages: email, SMS and URL. Each event (a message, a link, or a call that cannot yet be scored) carries
a channel, a time and identity tokens taken from its content: registered domains, phone numbers and an optional sender identity. A correlation
engine groups one recipient's events into time windows of 60 minutes, describes each window by 15 features
(scores per channel, how many events share an identity token, and the time span), and scores it with a gradient-boosting model trained on
simulated bundles of real messages. The bundle takes the highest window score; a window with one event keeps that event's detector score. An
event store keeps each recipient's events with the recipient and the identity tokens hashed (HMAC-SHA256), turns windows into campaigns, and
raises one alert per campaign when it first reaches the alert line of 0.5. Calls and video are stored and shown as "not assessed";
they never change a score and are never called safe.

## 4. Simulated, not measured on real data

The correlation results come from 12,000 **simulated** test bundles. The events are real held-out messages; the links between them
are constructed, because no public dataset links one attacker's events across channels. The simulation's mix: attack bundles with linked
events 30.0%, single attack events 10.0%, mixed unlinked 10.0%, benign linked
20.0%, benign unlinked 30.0%.

| Method (SIMULATED bundles, alert line 0.5) | Precision | Recall | F1 (95% CI) | False-positive rate (95% CI) |
|---|---|---|---|---|
| Single-channel: alert if any event reaches the line | 87.0% | 95.3% | 91.0% (90.4%-91.4%) | 14.1% (13.2%-15.1%) |
| Parallel multi-channel: fusion without link and timing features | 97.0% | 92.2% | 94.5% (94.2%-94.9%) | 2.8% (2.5%-3.3%) |
| Correlation model on the whole bundle | 97.0% | 92.9% | 94.9% (94.6%-95.3%) | 2.8% (2.5%-3.2%) |
| Deployed engine, 60-minute windows (what the API does) | 89.4% | 94.9% | 92.0% (91.5%-92.5%) | 11.1% (10.3%-11.9%) |

Source: `reports/comparison_metrics.json` and `reports/window_metrics.json`. 27 simulated linked attacks (0.8%)
have every event below the line; the deployed engine flags 18.5% of them. The alert line is tied to the simulation's mix,
and the risk is not a calibrated probability.

**What can honestly be said:** inside the window the engine beats single-channel alerting by a little, on simulated bundles, mainly through a
lower false-positive rate. The gain over the same model without link and timing features is small (AUC 0.9847 against
0.9874). The model is not stable on borderline bundles: a retrain on almost the same simulated data moved the hand-written TC-06
from 0.595 to 0.456. None of this has been tested on real coordinated attacks (0 real bundles, R2-10).

## 5. Not built: do not claim

- A voice detector and a deepfake (video) detector. No accessible data. Calls and video are "not assessed".
- The old draft's noisy-OR campaign score with time decay and sequence factors. Not built, not evaluated (owner, 7 Nov 2026).
- The old draft's window value, watch list, hash-chained audit log and voice module. The build keeps no audit log and no watch list.
  Keyed hashing of identities is built (HMAC-SHA256 in the event store, section 2); it was not compared with the old draft's wording.
- Any result on real multi-channel bundles.
- A calibrated probability.
- A message queue, streaming source, or mail, SMS or browser integration. Events reach the system only through the API.
- The numbers the old draft reported. They were generated, not measured. The retired list is in `reports/FINAL_NUMBERS.md`, section 9.
